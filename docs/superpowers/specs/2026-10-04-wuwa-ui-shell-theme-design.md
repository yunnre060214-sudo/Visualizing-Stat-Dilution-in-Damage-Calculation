# 鸣潮伤害可视化 UI 工作台与主题切换设计

日期：2026-10-04  
目标仓库：`yunnre060214-sudo/Visualizing-Stat-Dilution-in-Damage-Calculation`  
目标版本：UI v2

## 1. 背景与目标

当前版本已经具备伤害工作台、词条稀释、配装对比和循环时间轴入口，但页面把目录选择、面板输入、结果、Buff 审计和计算追踪同时铺在主内容区。信息本身完整，主次关系却不够清楚，用户需要在多个大卡片之间来回寻找当前任务和最终结论。

UI v2 的目标是把应用重构为侧栏工作台：左侧负责全局导航，中间只承载当前任务，右侧固定展示当前视图最重要的结论。深色和浅色主题使用同一套语义化设计变量，用户点击主题按钮时，新主题从按钮圆心以圆形幕布扩散到全屏。

成功标准如下：

1. 首屏能够直接区分“去哪里”“改什么”“结果是什么”。
2. 次要说明、导入导出和详细追踪默认不与核心输入争夺空间。
3. 桌面端高密度但不拥挤，移动端无需横向挤压桌面三栏。
4. 深浅主题覆盖全部现有组件、图表、错误状态和交互状态。
5. 主题切换动画从实际按钮位置开始，并在减少动态效果模式下立即完成。

本次不改变伤害公式、数据快照、业务状态结构和现有四个功能视图的能力边界，也不在本阶段实现循环时间轴业务功能。

## 2. 信息架构

### 2.1 桌面端外壳

宽度大于 1080 像素时使用三栏工作台：

1. 左侧侧栏宽度约 216 像素，固定品牌、四个功能入口、当前数据版本和主题切换按钮。侧栏随页面滚动保持可见。
2. 中间工作区使用 `minmax(0, 1fr)`，只展示当前视图的标题、核心输入和主要图表。
3. 右侧结果栏宽度约 320 至 360 像素，使用粘性定位展示当前视图最重要的结果；页面较长时结果仍可见。

应用最大宽度由当前 1480 像素提升至约 1680 像素，并保留紧凑边界。卡片继续采用直角和细边线，不引入大面积圆角容器。全局顶栏并入侧栏，释放垂直空间。

### 2.2 中等宽度

宽度为 760 至 1080 像素时，侧栏收窄为图标和短标签模式，右侧结果栏移动到中间工作区顶部，成为横向摘要条；核心输入和图表保持单列，不产生水平滚动。

### 2.3 移动端

宽度小于 760 像素时使用紧凑顶栏、底部功能导航和可展开结果面板：

1. 顶栏只保留品牌简称、数据版本和主题按钮。
2. 四个功能入口位于底部固定导航，每个入口同时提供序号与名称。
3. 当前视图的核心结果位于内容顶部的紧凑摘要中，点击后展开详细结果。
4. 编辑区按语义分组垂直排列，不复用桌面三栏宽度，也不使用遮挡主要内容的侧向抽屉。

底部导航会为页面预留安全区，兼容 iOS 底部手势区域。

## 3. 各视图布局

### 3.1 伤害工作台

中间工作区分为两个始终可见的主区和一个次级区：

1. “基础配置”包含角色、武器、伤害动作和目标，沿用现有目录数据与失效引用提示。
2. “面板参数”包含攻击、生命、防御、技能倍率、暴击率、暴击伤害、目标抗性、伤害加成和伤害加深。字段按基础面板、暴击、伤害乘区分组，避免一条长列表。
3. “详细分析”使用标签切换 Buff 来源与乘区追踪，同一时间只展示其中一个内容。

右侧结果栏固定显示期望伤害、未暴击伤害、暴击伤害、当前角色与目标摘要。无效输入时，结果栏保留结构并显示具体问题，不把错误退化为空白。

### 3.2 词条稀释

中间工作区上方为当前配置和预算口径，下方为主曲线。当前加成输入按攻击、暴击、增伤分组，预算口径与纵轴选择归入图表工具条。右侧结果栏显示下一份预算推荐、五项边际收益排名、当前基准伤害和暴击溢出提示。

移动端先显示推荐结论，再显示曲线和参数；图表可以横向滚动，但页面本身不能横向溢出。

### 3.3 配装对比

中间工作区保留 A/B 两套方案，但每套方案使用“目录选择”和“面板参数”两个可切换分区，避免一次展示全部字段。共享动作与共享目标开关放在两张方案卡之间的统一工具条。

JSON 导入导出和分享能力归入折叠的“配置工具”区域。右侧结果栏显示胜者、三类伤害差值、相对提升与斜率图；用户编辑任一方案时，结果栏实时更新。

### 3.4 循环时间轴

本阶段只重做占位页视觉，使其遵循新工作台外壳；不增加尚未完成的循环计算能力。右侧结果栏显示后续阶段将提供的输出清单，避免占位页看起来像可用功能。

## 4. 组件边界

新增通用布局和主题组件：

```text
src/
  app/
    AppShell.tsx
    Sidebar.tsx
    MobileNavigation.tsx
    WorkspaceFrame.tsx
    ResultRail.tsx
  theme/
    ThemeProvider.tsx
    ThemeToggle.tsx
    ThemeCurtain.tsx
    theme.ts
  styles/
    tokens.css
    global.css
```

`AppShell` 只负责响应式外壳和视图导航，业务视图仍由现有 feature 组件持有。`WorkspaceFrame` 接收标题、说明、主内容和结果内容，使四个视图使用一致骨架。`ResultRail` 处理桌面粘性结果栏、中等宽度摘要条和移动端展开面板。主题组件不依赖伤害业务状态，避免主题切换触发配置迁移。

现有功能 CSS 模块继续负责局部组件布局，但颜色、边线、阴影、输入背景和状态色必须改为语义变量，不再直接写死深色值。

## 5. 主题系统

### 5.1 状态与持久化

主题值为 `light | dark`。首次访问时读取 `prefers-color-scheme`，用户主动切换后写入独立的 `wuwa-theme` 本地存储键；后续访问优先使用用户选择。主题通过 `document.documentElement.dataset.theme` 应用，并同步 `color-scheme`，让原生表单控件使用正确配色。

主题状态与伤害配置分开保存。现有 `PersistedState` 不增加主题字段，因此不会改变伤害配置的迁移版本，也不会污染分享 URL。

### 5.2 设计变量

`tokens.css` 定义以下语义变量，并分别提供浅色与深色值：

```text
--page-bg
--sidebar-bg
--surface-1
--surface-2
--surface-elevated
--text-strong
--text-default
--text-muted
--border-subtle
--border-strong
--accent-primary
--accent-secondary
--positive
--warning
--negative
--shadow-panel
--chart-grid
```

深色主题延续当前青色与金色强调；浅色主题使用偏冷白背景、深灰蓝文字和降低饱和度的青色强调，避免纯白大面积刺眼。错误、警告和成功状态在两套主题中保持相同语义与足够对比度。ECharts 配置从当前主题读取文字、网格、提示框和系列颜色，主题变化后重新应用图表选项。

## 6. 圆形幕布动画

主题按钮点击时记录按钮中心相对视口的坐标 `(x, y)`，并计算该点到四个视口角的最大距离 `r`。首选实现使用 View Transitions API：

1. 在过渡回调中切换 `data-theme`。
2. 隐藏旧根节点的默认淡出动画。
3. 对新根节点应用 `clip-path: circle(0 at x y)` 到 `circle(r at x y)` 的动画。
4. 动画持续约 650 毫秒，缓动使用快速起步、平滑收尾的曲线。

不支持 View Transitions API 时使用 `ThemeCurtain` 降级：在按钮中心创建下一主题背景色的固定圆形遮罩，扩张到覆盖视口后提交主题，再快速淡出遮罩。降级动画仍从按钮位置开始，不退化为全屏闪烁。

当 `prefers-reduced-motion: reduce` 为真时跳过幕布，立即切换主题。动画期间主题按钮临时禁用，防止连续点击产生竞态；完成或异常时都必须清理过渡类名和遮罩。

## 7. 可访问性与交互细节

1. 侧栏与底部导航使用同一组可访问名称，并通过 `aria-current="page"` 标记当前视图。
2. 主题按钮的名称描述将要执行的操作，例如“切换到浅色主题”，而不是只朗读太阳或月亮图标。
3. 详细分析标签支持键盘焦点和明确选中状态；折叠区使用原生按钮及 `aria-expanded`。
4. 结果数值继续使用表格数字，颜色之外同时使用文字、符号和标签表达正负变化。
5. 浅色与深色主题的正文、边线、焦点环和状态色满足 WCAG AA 对比度目标。

## 8. 测试策略

单元与组件测试覆盖：

1. 首次访问跟随系统主题，手动切换后保存并在重新挂载时恢复。
2. 点击主题按钮时使用按钮中心作为动画原点，并在动画结束后清理状态。
3. View Transitions API 缺失和减少动态效果两条分支都能正确切换。
4. 四个视图在新侧栏中保持原有切换和状态持久化行为。
5. 伤害工作台的详细分析标签、配装对比配置工具和移动端结果面板正确展开与收起。

Playwright 覆盖桌面、中等宽度和移动端三组视口，验证导航可达、页面无横向溢出、主题切换后刷新仍保留、核心结果仍随输入变化。视觉验收同时检查深色与浅色截图，并在 GitHub Pages 子路径上完成线上冒烟测试。

## 9. 发布与兼容

实现不增加运行时依赖。主题动画使用浏览器原生能力与 CSS，降级方案保证 Firefox 或旧版 Safari 仍能完成同源扩散效果。现有本地伤害配置和分享链接保持兼容，用户升级后无需重置数据。

发布沿用当前 GitHub Actions 与 Pages 工作流。验收通过后更新 README 的 UI v2 说明，并确认线上页面的深浅主题、桌面三栏、移动端底部导航和参数联动均正常。

## 10. 验收标准

1. 桌面端左侧导航、中间任务区和右侧结果栏层级明确，常用结果无需滚动寻找。
2. 工作台、稀释和对比视图不再同时平铺全部次要内容。
3. 760 像素以下使用底部导航和可展开结果面板，不出现页面级横向滚动。
4. 深色与浅色主题覆盖所有视图、输入、图表、提示和状态色。
5. 主题动画从实际点击按钮处圆形扩散，减少动态效果模式立即切换。
6. 现有伤害计算、词条稀释、配装对比、持久化与分享能力保持通过。
7. 类型检查、单元测试、构建、端到端测试和 GitHub Pages 线上验证全部通过。
