# 鸣潮伤害与词条稀释可视化设计

日期：2026-10-03  
目标仓库：`yunnre060214-sudo/Visualizing-Stat-Dilution-in-Damage-Calculation`  
目标版本：鸣潮 3.7

## 1. 产品目标

本项目同时解决两类需求：一是让用户输入角色、装备、队伍与敌人后得到可追溯的伤害结果；二是用边际收益曲线解释攻击、暴击、暴击伤害、属性增伤、伤害加深等词条为何会出现稀释，以及下一份同等预算投入哪个乘区收益更高。

首版覆盖当前 3.7 的全角色与技能倍率、4 星和 5 星武器、声骸套装、共鸣链、常见队友 Buff、敌人等级与抗性，并提供 8 套有可靠动作轴来源的主流队伍循环预设。项目是非官方、非商业的静态网页，不提供账号登录、联网读取游戏账号、抽卡规划、自动操作游戏或云端存档。

## 2. 设计原则

1. 每个结果都可解释。最终伤害必须能展开为面板、倍率和各乘区的完整链路。
2. 数据与规则分离。游戏数据可随版本替换，计算代码不依赖具体角色名称。
3. 缺失机制显式暴露。无法可靠解释的条件标记为“需手动确认”，不得静默按零处理。
4. 静态优先。生产页面不依赖第三方 API 在线可用性，GitHub Pages 加载后可离线继续使用。
5. 版本可复现。数据快照、规则版本和循环来源共同写入构建元数据。

## 3. 技术架构

技术栈为 React、TypeScript、Vite、Vitest、Playwright 和 ECharts。应用通过 GitHub Actions 构建并部署到 GitHub Pages，Vite 的 `base` 使用仓库子路径，避免资源地址在 Pages 环境产生 404。

目录边界如下：

```text
src/
  data/          3.7 规范化快照、来源元数据、数据模式
  engine/        面板、单次伤害、Buff、时间轴、稀释分析纯函数
  presets/       声明式队伍与循环预设
  features/      工作台、稀释、对比、时间轴四个功能域
  components/    无业务状态的通用组件
  store/         URL 状态、本地持久化和迁移
scripts/         数据抓取、规范化、校验和版本更新脚本
tests/           单元、黄金样例、数据完整性与端到端测试
```

核心 API 保持窄而稳定：

```ts
buildPanel(loadout, context): PanelSnapshot
resolveHit(action, snapshot, target): HitResult
simulateRotation(rotation, team, target): RotationResult
compareMarginalValue(config, budget): MarginalValueResult
```

页面只消费这些结果，不在组件内重复实现公式。

## 4. 数据方案

构建脚本通过可替换的 `DataProvider` 适配器读取公开游戏数据源，首版适配 encore.moe API v2，并输出仓库内的规范化 JSON。生产页面只读取该 JSON，不在运行时请求数据源。每个快照记录游戏版本、抓取时间、来源 URL、原始记录校验和与规范化器版本。

首版数据范围包括：

1. 全部 3.7 共鸣者的 90 级基础属性、属性类型、武器类型、技能 1 至 10 级倍率、多段结构、伤害类型与缩放属性。
2. 全部 4 星和 5 星武器的 90 级基础属性、谐振阶 1 至 5 数值与可计算效果。
3. 共鸣链 0 至 6、固有技能、常见队友 Buff、声骸主副词条、套装效果与首位声骸效果。
4. 敌人等级、六属性抗性、防御相关参数，以及供用户手动覆盖的自定义目标。

角色图片只保存远程 URL，并提供名称首字和属性色占位图；图片加载失败不影响计算。游戏文本与美术资源归其权利人所有，仓库 README 标注非官方项目与数据来源。

## 5. 伤害模型

面板属性使用以下通式：

```text
面板攻击 = (角色基础攻击 + 武器基础攻击) × (1 + 攻击百分比总和) + 固定攻击
面板生命 = 角色基础生命 × (1 + 生命百分比总和) + 固定生命
面板防御 = 角色基础防御 × (1 + 防御百分比总和) + 固定防御
```

普通伤害结算为：

```text
有效倍率 = (原始技能倍率 + 倍率直接增加) × (1 + 倍率提升)
基础伤害 = 缩放属性 × 有效倍率
最终伤害 = 基础伤害
         × (1 + 伤害加成总和)
         × (1 + 伤害加深总和)
         × 承伤修正
         × 防御系数
         × 抗性系数
         × (1 + 最终伤害提升总和)
         × 暴击系数
```

防御系数使用：

```text
A = 800 + 8 × 攻击者等级
B = (800 + 8 × 敌人等级) × (1 - 防御降低) × (1 - 防御无视)
防御系数 = A / (A + B)
```

有效抗性记为 `r = 敌人抗性 - 抗性降低 - 抗性无视`，抗性系数分段为：

```text
r < 0       时：1 - r / 2
0 ≤ r < 0.8 时：1 - r
r ≥ 0.8     时：1 / (1 + 5r)
```

暴击结果同时输出非暴击、暴击与期望值。期望暴击系数为 `1 + clamp(暴击率, 0, 1) × (暴击伤害 - 1)`；暴击伤害使用游戏面板显示的总倍率口径。多段伤害逐段计算后求和，最终显示值按游戏可验证的取整口径处理，内部中间值保留精度。

特殊效应、谐度破坏、骇破和震谐使用独立伤害类型与公式适配器，避免强行塞入普通暴击伤害链。任何尚未验证的特殊机制在结果中标记其置信等级和手动修正入口。

## 6. 词条稀释模型

稀释分析以完整配置的反事实重算为准。系统复制当前配置，分别加入一个“预算单位”的攻击百分比、暴击率、暴击伤害、属性增伤、对应伤害类型增伤或伤害加深，再重跑同一单段伤害或同一循环。预算单位默认采用 3.7 数据中的一条中位有效副词条，用户也可切换为统一增加 10 个百分点。

每个候选属性输出绝对增伤、相对提升、每预算点收益、溢出损失和触发阈值。曲线横轴为继续投入的预算单位，纵轴可切换总伤害、相对提升或边际提升；当前配置、首次交叉点和暴击率 100% 等关键点均有标记。若新增属性改变 Buff 条件或资源阈值，曲线使用引擎逐点重算，不使用局部导数近似。

## 7. 循环模拟

循环是确定性的声明式事件序列，包含角色、动作、开始时间、持续时间、取消点、资源变化、Buff 开关、伤害事件与切人事件。引擎按时间顺序建立每次伤害发生时的属性快照，结算该次伤害并汇总总伤、DPS、成员贡献、Buff 覆盖率和资源收支。

首版提供 8 套主流队伍预设。候选队伍来自 3.7 深塔公开排行；只有能够从至少一份详细攻略或实测记录还原动作顺序、持续时间和 Buff 覆盖的队伍才进入预设。每个预设在清单中记录版本、作者或来源链接、采样日期、假设与尚未覆盖的取消技巧。对新角色尚无可靠实测轴的队伍，只允许进入自由组队与单段计算，不伪造精确循环。

首版不做自动最优轴搜索。用户可以调整预设中的武器、面板、链数和敌人，动作顺序保持预设定义；后续版本可增加高级时间轴编辑器。

## 8. 页面与交互

应用提供四个主视图：

1. 伤害工作台：左侧配置角色、装备、队伍和敌人，中间展示非暴击、暴击、期望伤害及逐乘区公式，右侧展示边际收益排序与未满足条件。
2. 词条稀释：显示多条边际收益曲线、当前面板位置、交叉点、阈值与“下一份预算”的明确推荐。
3. 配装对比：A/B 两套配置并排编辑，用斜率图和差值条比较单段、期望、循环总伤和 DPS。
4. 循环时间轴：显示三名角色动作区间、Buff 窗口、伤害脉冲、累计伤害曲线和成员贡献；点击事件打开当时的完整快照。

桌面端使用高密度三栏布局，移动端改为可折叠分区与底部视图切换。颜色不能成为唯一信息编码，曲线同时使用线型、标签和图例；所有输入可用键盘操作，动态结果使用节流后的无障碍播报。

## 9. 状态、分享与错误处理

配置以带版本号的 JSON 保存到 `localStorage`，更新数据模式时通过迁移函数升级。当前视图、角色、核心面板和比较模式可编码进压缩 URL，超出安全长度的完整时间轴只保存在本地并提供 JSON 导入导出。

数据缺失、引用失效、图片失败和无法解释的 Buff 条件都有独立错误状态。数值输入会进行范围校验，异常值保留原输入并显示原因，不自动替换成零。页面顶栏固定显示数据版本、规则版本与最近更新时间。

## 10. 测试与验收

测试分为四层：

1. 单元测试覆盖面板构建、各乘区、暴击上限、抗性分段、防御降低与无视、多段取整、Buff 条件和边际收益。
2. 数据测试确保所有技能、武器、Buff、角色和预设引用有效，角色与武器覆盖数量符合 3.7 快照清单。
3. 黄金测试保存手工复核的单段案例和 8 套循环结果；规则或数据更新导致变化时必须显式更新快照说明。
4. Playwright 覆盖桌面与移动端核心流程、刷新持久化、分享链接恢复、GitHub Pages 子路径和静态资源加载。

发布验收标准如下：

1. 任一 3.7 角色的任一已解析技能均可选择并完成伤害计算。
2. A/B 配装可以比较单段伤害、期望伤害、循环总伤与 DPS。
3. 稀释曲线随输入实时变化，并能指出暴击溢出和乘区交叉点。
4. 8 套主流队伍可生成可点击、可解释的循环时间轴。
5. 刷新后本地配置保持，分享链接能恢复核心配置。
6. GitHub Actions 的类型检查、单元测试、数据校验、构建与端到端冒烟测试全部通过。
7. GitHub Pages 线上首页和深链接均无 404，桌面与移动端没有阻断使用的布局溢出。

## 11. 交付顺序

实施按以下顺序收敛风险：项目骨架与 CI，公式引擎与测试，3.7 数据管线，单段工作台，稀释分析，A/B 对比，循环引擎与 8 套预设，响应式与无障碍，Pages 部署和线上验收。每个阶段都保留可运行的静态构建，避免最后一次性集成。
